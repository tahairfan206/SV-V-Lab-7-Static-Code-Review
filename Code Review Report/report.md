# Static Verification Code Review Report

| Line Number | Defect Type | Why it is a problem | Proposed Solution | Severity |
|---|---|---|---|---|
| **25–38, 133** | **Rule of Three Violation (Shallow Copy)** | `Game` defines a custom destructor to free raw pointers but lacks a copy constructor and copy assignment operator. `Game copy = game;` performs a shallow member-wise copy. When both objects go out of scope, both destructors attempt to free the exact same heap addresses, causing a double-free crash (`SIGABRT`). | Declare a deep-copy constructor and copy assignment operator, explicitly delete them (`= delete;`), or replace raw pointers with RAII wrappers like `std::vector<std::unique_ptr<Monster>>`. | **Critical** |
| **40–43** | **Buffer Overflow / Out-of-Bounds Write** | `monsters` is a fixed array of size `MAX_MONSTERS` (5). `spawnMonster` increments `monsterCount` without checking capacity. Spawning 6 monsters (line 119) writes to `monsters[5]`, causing heap/memory corruption. | Add a boundary check before insertion: `if (monsterCount >= MAX_MONSTERS) return;` or migrate to a dynamic `std::vector`. | **Critical** |
| **47** | **Assignment in Conditional** | `if (monsters[i]->id = id)` uses the assignment operator `=` instead of equality `==`. This overwrites `monsters[i]->id` with `id` and evaluates to `true` for any non-zero ID, causing the function to always return `monsters[0]`. | Replace assignment with comparison: `if (monsters[i]->id == id)`. | **Critical** |
| **54** | **Unchecked Null Pointer Dereference** | If `findMonster(id)` fails to find a match, it returns `nullptr`. `attackMonster` immediately dereferences `m->health` without checking if `m` is valid, triggering a segmentation fault (e.g., calling with ID 99 at line 123). | Add a null check before access: `if (!m) return -1;` (or handle the missing entity appropriately). | **High** |
| **55–56** | **Implicit Unsigned Promotion / Dead Code** | `dmg` is typed as `unsigned int`. In `m->health - dmg < 0`, `m->health` is promoted to `unsigned int`. Unsigned values can never evaluate to less than zero; if damage exceeds health, the value wraps around to ~4.29 billion, making the `< 0` check dead code. | Maintain signed types: `int dmg = damage;` and clamp explicitly: `if (damage >= m->health) { m->health = 0; return 0; }`. | **High** |
| **64** | **Off-by-One Loop Bound** | The loop condition uses `i <= monsterCount` instead of `i < monsterCount`. When `monsterCount == MAX_MONSTERS`, the loop reads `monsters[MAX_MONSTERS]`, accessing unallocated memory beyond the array boundary. | Change loop condition to strictly less than: `for (int i = 0; i < monsterCount; i++)`. | **High** |
| **70–73** | **Dangling Stack Reference** | `getMonsterLabel` returns a reference (`std::string&`) to a local stack variable (`label`). The storage for `label` is destroyed as soon as the function returns. Consuming this reference in `main()` causes Undefined Behavior. | Return the string by value instead of by reference: `std::string getMonsterLabel(int id)`. | **Critical** |
| **71** | **Unchecked Null Pointer Dereference** | `getMonsterLabel` calls `findMonster(id)` but does not verify `m != nullptr` before accessing `m->id` and `m->name`. Passing an invalid ID causes a crash. | Verify `m != nullptr` before formatting the string; return an error label if `m` is null. | **High** |
| **77** | **Uninitialized Variable Read** | `double sum;` is declared on the stack without initialization. Accumulating into it (`sum += ...`) reads indeterminate memory, resulting in Undefined Behavior and corrupted calculations. | Initialize the variable at declaration: `double sum = 0.0;`. | **High** |
| **80** | **Division by Zero** | If `monsterCount == 0`, evaluating `sum / monsterCount` causes an unhandled division by zero. | Guard the division: `if (monsterCount == 0) return 0; return sum / monsterCount;`. | **Medium** |
| **85–86** | **Use-After-Free (UAF)** | `defeatMonster` calls `delete m;` and immediately reads `m->name` on the next line for console output. Accessing deallocated memory invokes Undefined Behavior. | Print the monster's name before deallocating memory: save the name locally or swap the order of the statements. | **Critical** |
| **85, 36–37** | **Dangling Pointer & Double-Free** | `defeatMonster` frees the memory pointed to by `m`, but leaves the dangling pointer inside the `monsters[]` array without nullifying the slot or shifting elements. When `~Game()` executes, it calls `delete` a second time on the same pointer. | Remove the pointer from `monsters[]`, shift remaining elements down, and decrement `monsterCount` (or assign `monsters[i] = nullptr;` and guard `~Game()`). | **Critical** |
| **91** | **Integer Division Precision Loss** | `attack * armorPercent / 100` uses integer arithmetic because all inputs are `int`. The fractional result is truncated before being promoted to `double`, losing precision. | Force floating-point arithmetic by dividing by a double literal: `return (attack * armorPercent) / 100.0;`. | **Low** |
| **94–99** | **Missing Return Statement** | If `score <= 100` (such as `playerRank(50)` at line 128), execution falls off the end of a non-void function without a `return` statement, triggering Undefined Behavior. | Ensure all control paths return a value: add a fallback `else return 3;` (or appropriate rank). | **High** |
| **102, 105** | **Unbounded Buffer Overflow** | `name` is a fixed 10-byte heap buffer (`new char[10]`). `std::cin >> name;` does not constrain input length. Entering a string of 10 or more characters overwrites heap metadata, leading to memory corruption. | Use `std::string` for input handling, or limit extraction with `std::cin >> std::setw(10) >> name;`. | **High** |
| **102, 109** | **Mismatched Allocation / Deallocation** | Dynamic memory is allocated using array new (`new char[10]`), but freed using scalar delete (`delete name;`). In C++, mixing scalar `delete` with array `new[]` is Undefined Behavior. | Match array allocation with array deallocation: `delete[] name;` (or eliminate manual management using `std::string`). | **High** |
| **121** | **Memory Leak** | `Monster* bonus = new Monster(...)` allocates memory on the free store that is never added to `Game` or deallocated via `delete`. | Call `delete bonus;` before exiting `main()`, or wrap it in a smart pointer (`std::unique_ptr<Monster>`). | **Medium** |
