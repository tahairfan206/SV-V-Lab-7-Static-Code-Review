# Static Verification & Code Review Checklist

| Category | Result (Issue / OK) |
|---|---|
| **1. Initialization** | **Issue**<br>• **Uninitialized Variable Read:** In `Game::averageAttack()`, `double sum;` is declared without an initial value (`0.0`). Accumulating with `sum += ...` reads indeterminate memory, invoking Undefined Behavior.<br>• **Constructor Initialization Style:** `Monster` assigns fields inside the constructor body instead of using member initializer lists (`Monster(...) : id(i), name(n)...`). |
| **2. Pointers (null/delete)** | **Issue**<br>• **Use-After-Free (UAF):** `Game::defeatMonster()` executes `delete m;` before reading `m->name` for console logging.<br>• **Dangling Pointer & Double-Free:** `defeatMonster()` deletes `m` but does not nullify the pointer in `monsters[]` or shift the array elements. When `~Game()` runs, it calls `delete` on the same memory block again.<br>• **Dangling Stack Reference:** `Game::getMonsterLabel()` returns a reference `std::string&` bound to the local variable `std::string label`, which is deallocated when the function exits.<br>• **Unchecked Null Dereference:** `attackMonster()` and `getMonsterLabel()` dereference the return value of `findMonster(id)` without validating `m != nullptr`. Calling `attackMonster(99, 20)` causes a segmentation fault.<br>• **Mismatched Deallocation:** `readBoss()` allocates dynamic memory via `new char[10]` but deallocates using scalar `delete name;` instead of array delete `delete[] name;`.<br>• **Memory Leak:** `Monster* bonus = new Monster(...)` allocated on the heap in `main()` is never freed. |
| **3. Arrays/buffers** | **Issue**<br>• **Static Array Buffer Overflow:** `Game::spawnMonster()` inserts items without checking `monsterCount < MAX_MONSTERS`. Spawning 6 monsters into a fixed 5-slot array writes out of bounds at `monsters[5]`.<br>• **Unbounded Console Buffer Overflow:** In `readBoss()`, `std::cin >> name;` reads into a fixed 10-byte buffer (`char[10]`) without length limits, allowing strings $\ge 10$ characters to overwrite heap metadata. |
| **4. Loops** | **Issue**<br>• **Off-by-One Boundary Condition:** In `Game::totalMonsterHealth()`, the loop condition `for (int i = 0; i <= monsterCount; i++)` uses `<=` instead of `<`. At capacity, this reads `monsters[monsterCount]`, resulting in an out-of-bounds pointer read. |
| **5. Arithmetic** | **Issue**<br>• **Unsigned Underflow / Dead Branch:** In `Game::attackMonster()`, `dmg` is declared as `unsigned int`. In `m->health - dmg < 0`, `m->health` is promoted to `unsigned int`; an unsigned value is never negative, making the underflow check dead code.<br>• **Integer Truncation:** In `calculateDamage()`, `attack * armorPercent / 100` performs integer division prior to assigning to `double`, discarding fractional damage values.<br>• **Divide-by-Zero Risk:** In `Game::averageAttack()`, if `monsterCount == 0`, evaluating `sum / monsterCount` causes an unchecked division by zero. |
| **6. Control flow** | **Issue**<br>• **Assignment in Conditional:** In `Game::findMonster()`, `if (monsters[i]->id = id)` uses the assignment operator `=` instead of equality `==`. It overwrites the monster's ID and evaluates to `true` for non-zero IDs, returning the wrong element immediately.<br>• **Missing Non-Void Return:** In `playerRank()`, execution falls off the end of the function if `score <= 100`. Calling `playerRank(50)` results in Undefined Behavior. |
| **7. Function call** | **Issue**<br>• **Invalid Stack Reference Consumption:** In `main()`, `std::cout << game.getMonsterLabel(2)` consumes a reference to an already-popped stack frame.<br>• **Unhandled Error State Propagation:** Calling `game.attackMonster(99, 20)` passes an invalid ID directly into a function with no null-handling, triggering a crash at runtime. |
| **8. Classes** | **Issue**<br>• **Rule of Three Violation:** `Game` defines a custom destructor `~Game()` to clean up raw pointers, but lacks a copy constructor and copy assignment operator. Executing `Game copy = game;` performs a shallow member-wise copy, triggering a double-free crash when both destructors run.<br>• **Poor Encapsulation & Resource Management:** Member fields in `Monster` are fully public with no invariant validation, and `Game` manages resources with manual raw pointers rather than RAII containers (`std::vector` or `std::unique_ptr`). |
